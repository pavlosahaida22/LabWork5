# ЛР № 5 – RAG-система для роботи з документами

Інтерактивний асистент, який відповідає на запитання **лише на основі ваших документів** і показує джерела.
Демо-база – документація вигаданого електровелосипеда **VoltRide X** (4 документи в `data/docs/`).
Її можна замінити власними `.md`, `.txt`, `.pdf`.

## Архітектура
```
документи → loader → chunking → embeddings → FAISS (vectorstore/)
                                                   │
запитання → [rewrite] → retriever (similarity | MMR | BM25 | hybrid, k, фільтр) → промт → LLM → відповідь + джерела
```

| Файл / модуль | Призначення (пункт методички) |
|---|---|
| `rag/loader.py` | завантаження документів + метадані (джерело, назва, сторінка) – 5.2.4 |
| `rag/chunking.py` | розбиття на фрагменти (розділи Markdown → recursive splitter), метадані зберігаються – 5.2.5 |
| `rag/embeddings.py`, `rag/store.py` | ембединги (fastembed, багатомовна MiniLM) і векторне сховище FAISS, збереження у `vectorstore/` – 5.2.6 |
| `rag/retriever.py` | retriever: similarity, MMR, BM25, hybrid (RRF), фільтр за метаданими, параметр k – 5.2.7, 5.2.12 |
| `rag/pipeline.py` | системний промт із правилами, контекст, відповідь із посиланнями [1], [2], переформулювання запиту – 5.2.8–5.2.9 |
| `rag/llm.py` | Gemini / Claude / OpenAI, ключ зі змінної середовища або Secrets – 5.2.2 |
| `app.py` | інтерфейс Streamlit (чат, налаштування пошуку, джерела, перебудова індексу) – 5.2.10 |
| `build_index.py` | побудова й збереження сховища з командного рядка |
| `evaluate.py`, `eval/test_queries.json` | 14 тестових запитів (single / multi / absent) та експерименти з параметрами – 5.2.11–5.2.12 |
| `tests/smoke_test.py` | швидка перевірка без мережі й ключів |

## 1. Встановлення
```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 2. API-ключ (5.2.2)
Безкоштовний варіант – **Google Gemini**: https://aistudio.google.com → *Get API key*.
Ключ **не записується в код** – задайте його одним зі способів:
```bash
export GEMINI_API_KEY="..."                    # Linux/macOS
setx GEMINI_API_KEY "..."                      # Windows (потім перевідкрити термінал)
```
або скопіюйте `.streamlit/secrets.toml.example` → `.streamlit/secrets.toml` і впишіть ключ, або вставте його в поле «API-ключ» у бічній панелі застосунку. Файл `secrets.toml` у `.gitignore`.

Інші провайдери: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`. Назву моделі можна змінити в інтерфейсі.

> Станом на жовтень 2026 моделі Gemini 2.5 знімаються з підтримки, тому за замовчуванням вказано `gemini-3.1-flash-lite`. Якщо отримаєте помилку 404, змініть назву моделі в полі «Модель» на актуальну (список: https://ai.google.dev/gemini-api/docs/models).

Без ключа застосунок працює в режимі **«лише пошук»** – показує знайдені фрагменти.

## 3. Побудова сховища та запуск
```bash
python build_index.py --chunk-size 400 --chunk-overlap 60   # необов'язково: застосунок сам побудує індекс при першому запуску
streamlit run app.py
```
Перший запуск завантажує модель ембедингів (~220 МБ), це займає кілька хвилин.

## 4. Тестування та експерименти (5.2.11–5.2.12)
```bash
python evaluate.py                                    # режими пошуку × k
python evaluate.py --chunk-sizes 200 400 800          # вплив розміру фрагмента
python evaluate.py --generate --provider gemini       # відповіді LLM на всі тестові запити
```
Метрики: `hit_rate` (знайдено хоча б одне очікуване джерело), `full_recall` (знайдено всі очікувані джерела, ключово для запитів з кількох документів), `top_score_absent` (схожість найкращого фрагмента для запитів, відповіді на які немає в базі). Результати зберігаються в `eval/results.csv`.

**Що перевірити вручну в застосунку:**
- single: «Який запас ходу має VoltRide X в режимі Eco?» → відповідь з одного документа;
- multi: «Скільки діє гарантія на батарею і як її зберігати?» → поєднання `03_garantiya.md` і `02_obslugovuvannya.md`;
- absent: «Скільки коштує VoltRide X?», «Хто президент Франції?» → відповідь «У наданих документах немає інформації…»;
- вплив параметрів: змініть k, спосіб пошуку (MMR/BM25/hybrid), фільтр за документом, увімкніть переформулювання запиту, перебудуйте індекс з іншим розміром фрагмента.

Шаблон таблиці для звіту:

| Конфігурація | hit_rate | full_recall (multi) | Якість відповідей (single / multi / absent) | Висновок |
|---|---|---|---|---|
| similarity, k=4, chunk=400 | | | | |
| MMR, k=4 | | | | |
| hybrid, k=4 | | | | |
| chunk=200 / 800 | | | | |
| + query rewriting | | | | |

## 5. Розгортання на Streamlit Community Cloud
1. Завантажте проєкт у репозиторій GitHub (без `secrets.toml`; папку `vectorstore/` можна додати, щоб не будувати індекс на сервері).
2. https://share.streamlit.io → *Create app* → вкажіть репозиторій, гілку `main`, файл `app.py`.
3. *Advanced settings → Secrets*: вставте `GEMINI_API_KEY = "..."`.
4. *Deploy*. Посилання `https://<назва>.streamlit.app` додайте до звіту.

## Нотатки
- Модель ембедингів `paraphrase-multilingual-MiniLM-L12-v2` розуміє українську, але обробляє лише ~128 токенів, тому розмір фрагмента за замовчуванням – 400 символів. Для більших фрагментів змініть модель у `rag/config.py` (наприклад, `paraphrase-multilingual-mpnet-base-v2`, ~1 ГБ, повільніша).
- Режим `EMBEDDING_BACKEND=hash` призначений лише для офлайн-тестів (`tests/smoke_test.py`), для якісного пошуку не підходить.
- Кожне запитання обробляється незалежно (історія діалогу не передається в LLM).
